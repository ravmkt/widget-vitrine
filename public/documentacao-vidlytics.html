1. Visão Geral do Produto

Vidlytics é uma plataforma SaaS (Software as a Service) que permite a lojas virtuais de e-commerce adicionarem widgets de vídeo interativos diretamente em seus sites. O objetivo é aumentar engajamento, taxas de conversão e vendas através de conteúdo em vídeo — vídeos curtos estilo "stories", carrosséis de produtos em vídeo e grades de vídeos.

Problema que Resolve

Lojas de e-commerce tradicionais usam apenas imagens estáticas. Vídeos aumentam drasticamente a confiança do consumidor e a taxa de conversão. O Vidlytics permite que qualquer loja — especialmente na plataforma Yampi — adicione vídeos de produtos de forma simples, sem necessidade de conhecimento técnico avançado.

Padrões Arquiteturais

  • Multi-tenant SaaS: Cada loja é um "tenant" isolado com seus próprios dados, membros e configurações.
  • Context API: AuthContext para sessão, TenantContext para loja ativa.
  • Data Layer Abstraction: Camada db.ts abstrai operações de banco com fallback para localStorage.
  • RLS (Row Level Security): Segurança no nível do banco — usuários só acessam dados de suas próprias lojas.
  • Server-side Functions: Operações sensíveis (conversões, importação XML) em Edge Functions.

5. Autenticação e Multi-tenant

Fluxo de Autenticação

  1. SignUp: Usuário se cadastra com nome, email, senha e nome da loja
  2. Criação automática do tenant:
    • Registro em auth.users (Supabase Auth)
    • Criação de profiles
    • Criação de stores (a loja/tenant)
    • Criação de store_members (role: owner)
    • Criação de subscriptions (plano: Essencial, status: trialing)
    • Criação de usage_counters (mês atual, contadores zerados)
  3. SignIn: Login com email/senha via supabase.auth.signInWithPassword()
  4. Session Monitoring: AuthContext monitora onAuthStateChange (INITIAL_SESSION, SIGNED_IN, SIGNED_OUT, etc.)
  5. Route Guards:
    • ProtectedRoute — Redireciona para /login se não autenticado
    • GuestRoute — Redireciona para /dashboard se já autenticado
    • HomeGuard — Verifica estado (logado? tem settings?) e redireciona

Multi-tenant (Isolamento de Dados)

Cada loja tem seus próprios vídeos, stories, produtos, configurações e métricas. O isolamento é garantido por:

  • RLS Policies: Usuários só veem/editam dados onde store_id corresponde a uma loja onde são owner ou member
  • TenantContext — Resolve e mantém a loja ativa no contexto React
  • Funções SQL auxiliares (is_store_owner, is_store_member, user_has_store_access)

7. Edge Functions (Serverless)

As Edge Functions rodam em Deno Deploy (via Supabase) e operam server-side com a SUPABASE_SERVICE_ROLE_KEY.

7.1. yampi-conversion

Propósito: Webhook que recebe eventos de conversão/venda da plataforma Yampi.

Fluxo:

  • Recebe store_id, video_id, product_id, visitor_id, order_id, order_value, status
  • Verifica se a conversão já existe (dedup por order_id)
  • Se existe: atualiza status e valor
  • Se não existe: cria novo registro em conversions

Endpoint: https://wznvecurmisgoaijykbt.supabase.co/functions/v1/yampi-conversion

7.2. import-products-xml

Propósito: Importa produtos de um feed XML (formato Google Shopping) para o catálogo da loja.

Fluxo:

  • Recebe URL do XML + store_id
  • Faz parse do XML
  • Cria/atualiza produtos em products com origem xml

7.3. proxy-xml

Propósito: Proxy CORS para permitir que o frontend acesse feeds XML de terceiros (contorna restrições de same-origin policy).

7.4. fetch-thumbnail

Propósito: Gera ou recupera thumbnails de vídeos a partir de URLs externas.

11. Segurança e RLS

Visão Geral de RLS

Quase todas as 27 tabelas têm Row Level Security habilitado. As policies seguem estes padrões:

Leitura Pública (Widget no site do cliente)

Estas tabelas têm policies que permitem leitura pública (USING (true)) porque o widget precisa funcionar sem login no site do e-commerce:

  • videos — vídeos ativos
  • stories — stories ativos
  • products
  • story_videos, story_products

⚠️ Problemas de Segurança Identificados

  1. insights sem RLS: A tabela insights tem rls_enabled: false. Qualquer usuário com a chave anônima pode ler/modificar insights de TODAS as lojas.
  2. Policies auth.role() = 'authenticated' muito amplas: Tabelas como stores, profiles, store_members, subscriptions, store_settings, app_settings, conversions têm policies que dão acesso total a qualquer usuário autenticado, sem verificar se o usuário pertence à loja específica. Isto é parcialmente mitigado pelas funções SQL como user_has_store_access, mas as policies em si são amplas.
  3. products com policy de escrita muito aberta: "Usuários autenticados gerenciam products" permite que qualquer usuário logado faça CRUD em qualquer produto.

13. Considerações Técnicas

Camada de Dados (db.ts)

O arquivo src/lib/db.ts implementa uma camada de abstração que funciona como uma espécie de ORM simplificado. Cada entidade (videos, stories, products, etc.) tem métodos getAll(storeId), save(), remove() que tentam usar Supabase primeiro e fazem fallback para IndexedDB/localStorage quando o Supabase não está disponível. Isto permite desenvolvimento offline e resiliência.

Analytics (analytics.ts)

O sistema de analytics rastreia 12 tipos de eventos: view, play, pause, click, cta_click, product_click, whatsapp_click, like, share, comment, close, conversion. Os dados são enriquecidos com device_type, browser, referrer, page_url e session_id. As métricas de likes, comentários e conversões usam queries diretas às tabelas reais (não a tabela metrics) para máxima precisão.

Parser de Vídeo (videoEmbeds.ts)

O módulo videoEmbeds.ts implementa parsing robusto de URLs de vídeo, detectando automaticamente a plataforma e extraindo o ID para embed. Suporta YouTube (4 formatos de URL), Instagram (reels, posts, TV) e TikTok (vídeos e links curtos). A função isVideoPlayableNatively() determina se um vídeo deve usar <video> HTML5 (uploads) ou <iframe> (plataformas externas).

Performance

  • Build via Vite SWC para compilação rápida
  • React 19 com recursos mais recentes
  • React Query para cache de dados client-side
  • Code splitting natural via React Router (lazy loading implícito)

Estrutura de Migrações

O projeto possui 8 migrações SQL versionadas (0001-0008) cobrindo: base multi-tenant, suporte a auth, integridade pre-RLS, RLS de analytics, RLS de widget público, e colunas de appearances. Importante: Migrações são geradas automaticamente pelo sistema e não devem ser editadas manualmente.
